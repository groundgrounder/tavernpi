# tavern studio 创作规划

> tavernpi 内核的 GUI 外壳，独立项目、独立仓库（本目录即未来仓库根）。
> 类比浏览器之于 Chromium：故事引擎全部能力在内核，studio 是面向创作与游玩的图形外壳。
> 本文档是 studio 项目级事实来源。对内核的依赖以 tavernpi 创作规划（`../创作规划.md`）§10.2 为唯一契约边界。
>
> **文档结构约定**：与内核文档共用「契约/机制」术语（见内核文档头部约定）。本文档只承诺 **UX 层契约**（用户能在 GUI 里做什么）；引擎行为契约（回溯一致性、模式强制、零事实漂移等）一律引用内核文档相应条目，不转述、不复制——避免双事实来源漂移。

## 1. 定位与形态

- **嵌入方式（已决策）**：以 npm 库形式同进程嵌入 tavernpi 内核，不走 RPC。
- **技术选型**：未定，候选 Tauri / Electron。S0 定案。选定前的硬约束：内核以 Node/TS 库形态分发，选型必须支持同进程嵌入与直接函数调用。
- **不做**：任何故事引擎逻辑（turn pipeline、subagent、快照、校验全部在内核）；不自己实现模式——三模式是内核级强制预设（内核规划 §10.1），studio 只呈现与提供配置入口。UI 侧绕过模式在架构上不可能，因为过滤与校验在内核查询层。

## 2. 能力（契约：给用户）

以下为 studio 对用户的承诺面；各能力的底层行为契约归内核文档，本节不转述。

- **游玩界面**：叙事阅读流、分支/swap 操作、模式对应的输入渠道（创造模式含剧情大纲指令输入；生存/冒险模式的输入校验反馈 UX）。
- **编辑器**：
  - 世界观/世界书条目、角色卡（轻量格式，内核规划 §4.1）、卡包管理；
  - NPC 设定：对 DB 中特征/记忆/关系的直接编辑——必须走内核写入 API（内核规划 §6.1 写者例外），禁止绕过；
  - 提示词编辑器：可视化编辑内核规划 §6.5 的各层提示词（内置/全局/卡包/故事级），显示当前生效层与覆盖链。
- **查看器**：
  - 故事树（浏览/回溯/fork/clone，回溯经内核 `navigateTree` 挂钩触发快照恢复）；
  - DB 浏览器（模式过滤由内核查询层执行，studio 不过滤）；
  - 时钟与事件时间线；
  - turn pipeline 运行观测（各 subagent 的输入/输出/耗时/成本，来自内核 pipeline 事件流）。
- **agent 配置界面**：各角色模型、thinking level、启用开关；模式管理（创造/生存/冒险）。

## 3. 对内核的依赖（协作契约：对内核项目）

依赖内核 API 承诺面（内核规划 §10.2）：故事生命周期（创建/加载/分支/回溯）、带模式过滤的 DB 查询、受信任的 DB 写入 API、提示词分层管理、agent/模型配置、模式管理、pipeline 事件流。

纪律：

- 内核 API 在 M6 定型前，studio 只依赖已收敛子集，并在 package 依赖中锁定内核版本；
- 内核 API 定型后的语义变更走版本化，studio 升级内核版本时显式适配，不静默跟随；
- studio 侧发现的内核能力缺口，回提到内核规划（改内核），不在 studio 内造引擎逻辑的补丁层。

## 4. 里程碑

- **S0 技术选型**：Tauri vs Electron spike——同进程嵌入 Node 库的可行性、包体、自动更新、Web 技术栈复用度。产出选型决策 + 空壳 app 跑通「嵌入内核、创建故事、发一轮输入」。
- **S1 壳与游玩主线**：故事生命周期（创建/加载/分支/回溯）+ 最小叙事阅读与输入界面。依赖内核 M2（故事 DB 与生命周期 API 可用）。
- **S2 查看器线**：故事树、DB 浏览器、时钟与事件时间线、pipeline 运行观测。依赖内核 M4（pipeline 事件流完整）。
- **S3 编辑器线**：卡/世界书/NPC/提示词编辑器、卡包管理。依赖内核 M5（卡包系统、提示词分层 API）。
- **S4 模式与配置 UX**：三模式呈现与切换、agent 配置界面、输入渠道校验的反馈 UX、创造模式剧情大纲指令入口。依赖内核 M6（模式预设实现、API 定型）。

里程碑对齐原则：studio 里程碑不早于其依赖的内核里程碑；内核 M6（API 定型）前 studio 不承诺任何对外发布。
